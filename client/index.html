How I
Work

Less about frameworks, more about how a system of people and code stays sane as it grows. A rough version of the loop I run on most projects:

01

Find the real constraint

Usually it isn't the one in the ticket. I dig until I find the thing actually limiting the system.

02

Prototype in the ugly version

A working, unstyled thing beats a polished mockup for deciding if an idea survives contact with data.

03

Instrument before you optimize

No performance work starts without a number to move. Otherwise it's just vibes with extra steps.

04

Leave it better documented

The next person touching this code is probably me, in six months, having forgotten everything.
